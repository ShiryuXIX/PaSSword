- 2026-11-18 (actualización posterior): El propietario autorizó explícitamente que Firebase pueda recuperar las llaves. Android y Windows ahora generan llaves AES-256 aleatorias para bóvedas nuevas y las guardan en `users/{uid}/vault/recovery`; al iniciar sesión con Google, las validan y abren la bóveda automáticamente. Las reglas permiten crear la llave una sola vez y niegan lectura a otras cuentas, actualizaciones y borrados. Firebase y los administradores del proyecto pueden leerla y descifrar las credenciales; este cambio sacrifica el secreto criptográfico frente al administrador.
- 2026-11-18: Las bóvedas Android existentes pueden migrarse tras verificar la clave maestra o un desbloqueo local válido. En Windows, la llave local no exportable no se puede migrar; hace falta la clave antigua una vez. Se distinguen las llaves nuevas con `RANDOM-AES-256` y las heredadas con PBKDF2. Se actualizaron README, requisitos, arquitectura, seguridad y `memory.md`; hay pruebas de formato/compatibilidad y reglas Firestore (lectura solo por el dueño; no reemplazar/borrar la llave ni rotar metadata). Se añadieron guardas contra cambios de cuenta durante lecturas. Análisis Dart, pruebas Flutter, build APK debug, pruebas Node, bundle Windows y prueba Firestore Emulator finalizaron correctamente. No se desplegaron reglas ni se publicaron versiones.
